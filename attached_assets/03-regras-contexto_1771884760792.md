# Módulo 3 — Regras e contexto

Baseado em: [Rules | Cursor Docs](https://cursor.com/docs/context/rules)

---

## O que são Rules

**Rules** são instruções em nível de sistema para o Agent. Elas agrupam prompts, scripts e fluxos, facilitando gerenciar e compartilhar padrões no time.

O Cursor suporta quatro tipos de regras:

| Tipo | Onde ficam | Escopo |
|------|------------|--------|
| **Project Rules** | `.cursor/rules` | Codebase (versionado) |
| **User Rules** | Configurações do Cursor | Global (seu ambiente) |
| **Team Rules** | Dashboard | Time (planos Team e Enterprise) |
| **AGENTS.md** | Raiz do projeto | Instruções em markdown simples |

---

## Como as regras funcionam

Modelos de linguagem não mantêm memória entre completions. As regras fornecem **contexto persistente e reutilizável** no nível do prompt.

Quando aplicadas, o conteúdo da regra é incluído no início do contexto do modelo, dando à IA orientação consistente para gerar código, interpretar edições ou ajudar em fluxos.

---

## Project Rules

Ficam em **`.cursor/rules`** como arquivos markdown e são versionados. Podem ser escopadas por padrões de path, invocadas manualmente ou incluídas por relevância.

Use para:

- Padronizar estilo ou decisões de arquitetura  
- Automatizar fluxos ou templates do projeto  
- Codificar conhecimento de domínio do codebase  

### Estrutura de pastas

Cada regra é um arquivo `.md` ou `.mdc`. Em `.mdc` você pode usar frontmatter com `description` e `globs` para controlar quando a regra é aplicada.

```
.cursor/rules/
  react-patterns.mdc    # Regra com frontmatter (description, globs)
  api-guidelines.md     # Regra em markdown simples
  frontend/
    components.md
```

### Tipos de regra

| Tipo | Comportamento |
|------|----------------|
| **Always Apply** | Aplicada em toda sessão de chat |
| **Apply Intelligently** | Quando o Agent achar relevante (baseado na description) |
| **Apply to Specific Files** | Quando o arquivo bate com o padrão (globs) |
| **Apply Manually** | Quando @-mencionada no chat (ex: `@minha-regra`) |

Exemplo de anatomia:

```markdown
---
globs: ["**/services/*.ts"]
alwaysApply: false
---

- Use nosso padrão RPC interno ao definir serviços
- Use sempre snake_case para nomes de serviços.

@service-template.ts
```

### Criar uma regra

- Comando: **"New Cursor Rule"**  
- Ou: **Cursor Settings > Rules, Commands**  
- Cria um novo arquivo em `.cursor/rules`. Nas configurações você vê todas as regras e o status.

## Boas práticas

Regras boas são **focadas, acionáveis e com escopo definido**.

- **Referencie arquivos** em vez de copiar o conteúdo — mantém regras curtas e evita desatualização.  
- Reaproveite regras quando repetir os mesmos prompts no chat.  
- Evite orientações vagas; escreva como documentação interna clara.  
- Inclua exemplos concretos ou arquivos de referência.  
- Divida regras grandes em várias regras menores e composáveis.  
- Mantenha regras com menos de ~500 linhas.

### O que evitar

- Duplicar o que já está no código: aponte para exemplos canônicos.  
- Instruções para edge cases raros: foque em padrões que você usa com frequência.  
- Documentar todo comando possível: o Agent já conhece npm, git, pytest etc.  
- Copiar guias de estilo inteiros: use um linter; o Agent já conhece convenções comuns.

Comece simples. Adicione regras quando o Agent repetir o mesmo tipo de erro. Não otimize demais antes de entender seus padrões.

**Dica:** versionar regras no Git beneficia todo o time. Quando o Agent errar, atualize a regra. Você pode até marcar `@cursor` em um issue/PR no GitHub para o Agent sugerir atualização da regra.

---

## Formato do arquivo de regra

Frontmatter controla a aplicação; o resto é o conteúdo da regra.

```yaml
---
description: "Padrões para componentes frontend e validação de API"
alwaysApply: false
---

...conteúdo da regra...
```

Se `alwaysApply` for `true`, a regra é aplicada em toda sessão. Caso contrário, a `description` é usada pelo Agent para decidir se aplica.

## Team Rules

Nos planos **Team** e [Enterprise](https://cursor.com/docs/enterprise), admins criam e aplicam regras para toda a organização pelo [Cursor dashboard](https://cursor.com/dashboard?tab=team-content).

- **Enforce this rule:** quando ativado, a regra é obrigatória e não pode ser desligada pelo usuário.  
- **Enable this rule immediately:** ativa assim que criada; se desmarcado, fica como rascunho até ser ativada.

Ordem de precedência: **Team Rules → Project Rules → User Rules**. Em conflito, a fonte que vem primeiro prevalece. Team Rules são texto livre (sem pastas nem metadados como `globs`/`alwaysApply`).

## Importação de regras

### Regras remotas (GitHub)

Em **Cursor Settings → Rules** → **+ Add Rule** ao lado de Project Rules → **Remote Rule (Github)**. Cole a URL do repositório que contém a regra. O Cursor sincroniza e mantém atualizado.

### Agent Skills

O Cursor pode carregar regras de [Agent Skills](https://cursor.com/docs/context/skills), um padrão aberto para estender agents. Skills importados são sempre aplicados como regras “decididas pelo agent” (relevância por contexto). Ative/desative em **Cursor Settings → Rules**.

## AGENTS.md

Arquivo markdown simples na **raiz do projeto** (ou em subdiretórios) como alternativa leve a `.cursor/rules`.

- Sem metadados nem configuração complexa.  
- Bom para instruções simples e legíveis.

Exemplo:

```markdown
# Instruções do Projeto

## Estilo de código
- Use TypeScript em arquivos novos
- Prefira componentes funcionais em React
- snake_case para colunas no banco

## Arquitetura
- Padrão de repositório
- Lógica de negócio em camadas de serviço
```

---

## User Rules

Definidas em **Cursor Settings → Rules**, aplicam-se em **todos os projetos**. Usadas pelo Agent (Chat). Úteis para estilo de resposta ou convenções pessoais, por exemplo:

```
Responda de forma concisa. Evite repetição desnecessária ou linguagem de preenchimento.
```

---

## Legado: .cursorrules

O arquivo **`.cursorrules`** na raiz ainda é suportado mas está em depreciação. Prefira migrar para **Project Rules** ou **AGENTS.md**.
